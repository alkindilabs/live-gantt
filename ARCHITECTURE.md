# Architecture

## Sources and ownership

[sources.py](live_gantt/sources.py) owns discovery, source validation and transcript reconstruction. `SourceStore` is a stateful data record holding byte offsets and parsed history, with serialized access. It reads Claude Code's configuration root selected by `CLAUDE_CONFIG_DIR`, falling back to the standard per-user directory. Task files are the authoritative current plan. Parent transcripts provide task creation, the first start, the last completion and progress history. Deleted task files disappear from the plan even when their history remains in the transcript.

Sessions are the union of task list directories and parent transcripts. Picker ordering uses parent transcript and task-file modification times. `RECENT_SESSION_WINDOW` in the source module defines the 14-day discovery window; discovery marks each entry `recent` and reads title and working directory from a bounded prefix only for recent sessions. Older entries contain identifier/date with the identifier as title and an empty project, without opening their transcript or custom-title file. Selected-session reads reconstruct the full transcript and resolve identity lazily, including identity after the bounded prefix. A custom title overrides the first user prompt.

Parent and subagent transcripts are scanned by byte offset. Complete records are consumed, including a valid final record without a newline; an incomplete trailing record waits for an append. A shrink, file replacement or same-length rewrite resets the cache. Relevant substrings are checked before decoding records, while timestamps are extracted for activity tracking. Malformed records are skipped. This makes normal polling proportional to appended data; the first selected-session read still scans its history.

Subagent metadata supplies descriptions and roles; their transcripts supply first/last activity and the latest tool description or name. Parent task notifications determine terminal state, with background-task-to-agent aliases recovered from tool results when available. Without a terminal notification, an agent becomes silent after 30 minutes. Task metadata assigns agents to task sub-bars; unassigned agents are left for the browser to filter to its visible window. External runs remain live until explicitly ended, with log modification time as their latest activity. A run that declares a positive integer `pid` and has not ended records whether that process exists, probed with signal zero: no signal is delivered, and any refusal other than an absent process counts as alive. Journals are scanned incrementally for finished result lines. All source paths are read-only; journal/log paths resolve relative to the task directory unless absolute or home-relative.

Each known metadata field validates independently and reports warnings on its task. Invalid estimates stay unknown, invalid weights revert to one, and invalid progress reverts to zero. Unknown keys carry no scheduling meaning. Normalized records, including sanitized metadata, form the boundary to projection, freshness and transport. Each task also records its file's modification time and whether it parsed; each state records its parent transcript's modification time. `plan(list_id)` normalizes one session's task files without opening its transcript, for callers that must stay cheap on every turn.

Claude Code file layouts are private, unversioned inputs. The invented-data [compatibility fixture](tests/fixtures/claude-code-2.1.292) preserves observed task files, transcript envelopes, tool results and subagent records from Claude Code 2.1.292. Its [boundary test](tests/test_compatibility.py) reads the complete session and projects its plan. This pins discovery, history reconstruction, agent association and cross-lane forecasts while keeping personal transcript content out of the repository.

## Projection

[schedule.py](live_gantt/schedule.py) owns the pure `project(tasks, now)` function. It copies normalized inputs and returns enriched tasks, milestone summaries and projection warnings. Historical actual times never depend on estimates. Missing history stays missing. A completed task without an end is available now for dependency purposes and has no invented actual bar.

Each lane reserves all already-running work before scheduling pending tasks in identifier order. Completed tasks do not interrupt the remaining lane chain. Multiple simultaneously running tasks preserve observed reality and produce warnings; pending work waits for all of them. Explicit `blockedBy` edges add cross-lane prerequisites. A dependency graph schedules each pending start at the latest of now, its lane predecessor's finish and all blocker finishes. A pending task with a known forecast is `queued` when direct unfinished prerequisites end after now; `waitingFor` lists their identifiers in natural order. Missing blockers and cycles suppress dependent forecasts and set `blocked` on the affected tasks, including successors. Unestimated-only paths remain distinct from blocked and queued work: an unestimated task stops its downstream lane projection rather than assuming zero duration.

An elapsed-hours Program Evaluation and Review Technique (PERT) estimate supplies mean `(low + 4 * likely + high) / 6` and standard deviation `(high - low) / 6`. Running work has remaining fraction `1 - max(progress, liveProgress) / 100`, measured from now. Zero progress beyond the expected elapsed duration marks overrun. Pending work uses its whole estimate. Dates outside the supported calendar produce warnings and unknown projections.

Milestone completion uses explicit task progress and relative weights: completed counts fully, in-progress counts proportionally, pending counts zero. The summary exposes `hasRemaining` and `hasEstimate`; the latter means at least one remaining task has a valid estimate, independently of whether its dependency forecast is known. The 50th-percentile (P50) date is the latest expected finish. For the 90th-percentile (P90) forecast, variance accumulates once per remaining task on the controlling prerequisite chain, scaled by the square of the remaining fraction. A prerequisite with the latest mean controls a join, with larger variance breaking ties; shared prerequisites are not counted twice. The latest chain end plus `1.2816` standard deviations supplies P90. This assumes independent task durations and approximates joins by their controlling chain. Unknown required durations keep the milestone forecast unknown.

## Freshness

[freshness.py](live_gantt/freshness.py) owns the pure `assess(tasks, transcript_updated, now)` function, the single definition of when a plan is stale. It reads the same normalized task records as projection and returns `stale`, `findings` (`rule`, `taskId`, plain-sentence `message`), `sinceChangeSeconds` from the newest task-file change, and `sessionActive`. A session is active when its parent transcript changed within five minutes, inclusive. Rules: an unfinished task lacks a valid estimate or a lane; an in-progress task has no numeric progress; an in-progress task file has not changed for fifteen minutes, inclusive, while the session is active; a run that has not ended names a missing log, or a log unchanged for ten minutes, inclusive, while the session is active; a run's declared process has exited and its log, if any, shows no life. A log still being written outweighs an exited or reused process identifier, and an exited process replaces the quiet-log finding for the same run. Run findings carry an `observed` phrase the chart shows next to the declared state. Completed, deleted and unreadable tasks produce no findings, so a half-written task file never reports a plan as stale. The scheduling fields are defined here; [the TaskCreate hook](hooks/task_created.py) imports them rather than keeping its own list.

## Local transport and idle behavior

[server.py](live_gantt/server.py) binds `ThreadingHTTPServer` exclusively to `127.0.0.1`. Request parsing checks that exactly one Host header equals `127.0.0.1:<bound-port>` or `localhost:<bound-port>` before dispatching any method. Fixed static routes prevent filesystem traversal. Responses have no cross-origin resource sharing headers and include a same-origin content security policy. JavaScript Object Notation (JSON) values are serialized without non-finite numbers. The browser renders source text through text nodes.

The server exposes fixed assets, the session index, a selected-session snapshot and Server-Sent Events (SSE). The fixed `/favicon.ico` route serves an inline Scalable Vector Graphics (SVG) two-bar mark; its colors derive from the page stylesheet's base `done` and `running` tokens. `Monitor` owns source access, cached source hashes and reader counts. It starts no polling worker until a stream is watched, then checks sources every two seconds. The final reader disconnect wakes and terminates the worker. Explicit requests can read sources without creating a background poller. Stream handlers detect closed sockets while waiting, and bound writes avoid retaining stalled clients indefinitely. Heartbeats run only for connected streams.

Each selected session's normalized source model is hashed independently of wall-clock projections, together with its freshness verdict: the findings and session activity at the poll's time, without the seconds-since-change counter. Staleness that arrives with time alone therefore still produces a `state` event, while a stale plan re-sends at most when a finding's message changes, about once a minute. Only changed source models or verdicts produce full `state` events. Index changes produce `lists` events. A comment and a timestamped `heartbeat` event are sent every 15 seconds, allowing the page to distinguish source inactivity from a disconnected connection. A normal state request recalculates projected dates even if its source hash is unchanged. The scheduler exports the overrun deadline and whether each milestone has remaining work so the browser can advance time without reimplementing scheduling rules.

## Browser and process lifecycle

[app.js](live_gantt/static/app.js), [style.css](live_gantt/static/style.css) and [index.html](live_gantt/static/index.html) make one buildless, offline page. The picker shows recent sessions first and reveals older entries through Show older sessions; only selecting an older entry loads its identity, which is retained in the selected option across index updates. The browser owns zoom, scrolling, visible-agent filtering and local advancement from the model's projection timestamp. Zoom defaults to 12 hours with now at the existing one-quarter past share; a validated local-storage preference overrides that default. Storage reads and writes are guarded so unavailable storage does not affect rendering. It maintains its own now line without asking the server for clock-only updates. Scrolling pauses following; the user can resume it.

Milestones with estimated remaining work use one horizontally scrollable row of compact name/share/P50/P90 cards. Finished milestones share one Done line, and milestones with no estimated remaining tasks share one Unestimated line. This bounds the summary height rather than adding card rows. The browser renders queued state and prerequisite identifiers supplied by projection; it does not reconstruct dependency rules. Likewise it renders freshness without reconstructing its rules: a stale verdict shows a banner listing each finding's message above the milestones, and each in-progress task's subtitle shows how long ago its task file changed, advanced locally, plus `declared running; observed: ...` for each run finding's observed phrase. Bar labels are measured after insertion: labels that fit align inside the right edge, while longer labels sit just after the bar without clipping or ellipsis. Labels extending beyond the visible window remain horizontally scrollable. Rows are one 24-pixel line each; a task's subtitle text lives in its tooltip, and focus and hover expose task detail. `RECENTLY_FINISHED_WINDOW` in the browser (two hours) defines recently finished: completed tasks that ended earlier, or have no end, fold into one summary row per lane and milestone showing the count and worked hours, and the rest stay full rows. A task's finished or failed agent attempts draw as small marks under its bar with an attempts badge; running and silent agents keep their own rows. Clicking a summary row or badge expands it, and the expanded keys, scoped by session, are the only other browser preference persisted through the same guarded local storage as zoom. Patterns and outlines distinguish statuses, system fonts use tabular numerals, and reduced motion disables pulses.

[__main__.py](live_gantt/__main__.py) selects the configuration root and fixed-loopback port and shuts down on interruption or termination. It starts no source work by itself. Only the browser's zoom and expansion preferences are persisted by the running application; transcripts reconstruct session history after downtime.

## Plugin and task planning

[The plugin manifest](.claude-plugin/plugin.json) owns the release version and plugin identity. [The marketplace](.claude-plugin/marketplace.json) refers to the repository root as its only plugin, so a checkout serves as both. Components use Claude Code's standard root directories. Repository and licence metadata remain unset until the maintainer chooses them.

[The live-gantt skill](skills/live-gantt/SKILL.md) is the single task-metadata contract for agents, including task-level dependencies. The README points there. [The TaskCreate hook](hooks/task_created.py) reads the successful tool response and original metadata, then adds advisory context when scheduling fields are missing. It never writes tasks or blocks tool use; malformed input produces no output. [The hook registration](hooks/hooks.json) invokes scripts through the plugin root so discovery is independent of the session's working directory.

[The freshness hook](hooks/freshness.py) applies the same `assess` to the session named by each hook event: `plan` reads its task files, and the event's transcript path supplies session activity, so no transcript is scanned. On `Stop` it blocks the end of a turn with one paragraph naming every finding, at most once per five minutes per session and never while a stop hook is already active. `UserPromptSubmit` adds the same paragraph as context on every prompt with findings. `PostToolUse` for every tool adds it at most once per five minutes; inside that window it reads only its state file and exits, because it runs after every tool call. The cooldown times live in one JSON state file per session under `CLAUDE_PLUGIN_DATA`, or else the installed-files directory; when that file cannot be written the hook stays silent rather than risk repeating itself. Unreadable task files and malformed events produce no output, and every failure exits successfully. It never writes tasks or transcripts.

[The open command](commands/open.md) checks the local server using its own address constants. When the server does not answer, it explains the persistent installation and asks before invoking it. The plugin can therefore guide task planning without installing a service.

## Installation and service lifecycle

[installation.py](live_gantt/installation.py) owns platform selection, stable data paths, service rendering, copying and removal. [The install](scripts/install.sh) and [uninstall](scripts/uninstall.sh) entry points only select the module action; the existing launchd entry points delegate to them. Python is the interpreter that runs the installer, checked against the minimum supported version before installation. No package installation is involved.

The service runs a copied package in per-user data storage, independent of the replaceable plugin cache. macOS uses the user's Library Application Support directory. Linux uses an absolute `XDG_DATA_HOME` or the standard local-share fallback; service configuration similarly respects an absolute `XDG_CONFIG_HOME`. A replacement package is staged in that directory before stopping the service, then replaces the previous package as a whole so removed source files cannot survive an update. The installed version is written only after service registration succeeds. A failed registration reports an error and leaves the previous version marker, allowing a later session to retry an upgrade. Installation is not a rollback transaction.

[The launchd template](launchd/local.live-gantt.plist) owns its agent label and priority policy: a standard process at niceness 10 with low-priority input/output. The renderer supplies the resolved Python interpreter, stable working directory and user log. The background process type would starve the chart under load; idleness comes from doing no work without a reader. [The systemd user unit](systemd/live-gantt.service) uses niceness 10 and best-effort input/output priority 7, the lowest non-idle priority. It starts at user login and logs to the user journal. Template rendering quotes paths and escapes systemd specifiers; the command disables environment expansion to preserve literal dollar signs in executable paths.

Explicit `CLAUDE_CONFIG_DIR` settings are stored beside the installed package and reused when an upgrade does not supply that variable. An explicitly empty value clears the override. The installer never changes Claude Code's files. Uninstall stops and unregisters the service and removes the copied package, saved configuration and version marker while retaining logs.

[The SessionStart hook](hooks/session_start.py) shares the installer's path selection and version filename. It reads the version marker first, then compares numeric stable release versions against the plugin manifest. An absent, malformed, equal or newer installed version produces no output and no service operation. An older installed version invokes the installer to refresh and restart that opted-in service. Errors are silent at this advisory boundary; the open command exposes installation errors interactively. Removing the version marker on uninstall preserves the user's choice across later sessions. Unchanged sessions do no copying or service work.
