# Architecture

## Sources and ownership

[sources.py](live_gantt/sources.py) owns discovery, source validation and transcript reconstruction. `SourceStore` is a stateful data record holding byte offsets and parsed history, with serialized access. It reads Claude Code's configuration root selected by `CLAUDE_CONFIG_DIR`, falling back to the standard per-user directory. Task files are the authoritative current plan. Parent transcripts provide task creation, the first start, the last completion and progress history. Deleted task files disappear from the plan even when their history remains in the transcript.

Sessions are the union of task list directories and parent transcripts. Picker ordering uses parent transcript and task-file modification times. Discovery obtains title and working directory from a bounded prefix; selected-session reads reconstruct the full transcript and can recover identity after that prefix. A custom title overrides the first user prompt. The discovery scan avoids reading every project's entire transcript.

Parent and subagent transcripts are scanned by byte offset. Complete records are consumed, including a valid final record without a newline; an incomplete trailing record waits for an append. A shrink, file replacement or same-length rewrite resets the cache. Relevant substrings are checked before decoding records, while timestamps are extracted for activity tracking. Malformed records are skipped. This makes normal polling proportional to appended data; the first selected-session read still scans its history.

Subagent metadata supplies descriptions and roles; their transcripts supply first/last activity and the latest tool description or name. Parent task notifications determine terminal state, with background-task-to-agent aliases recovered from tool results when available. Without a terminal notification, an agent becomes silent after 30 minutes. Task metadata assigns agents to task sub-bars; unassigned agents are left for the browser to filter to its visible window. External runs remain live until explicitly ended, with log modification time as their latest activity. Journals are scanned incrementally for finished result lines. All source paths are read-only; journal/log paths resolve relative to the task directory unless absolute or home-relative.

Each known metadata field validates independently and reports warnings on its task. Invalid estimates stay unknown, invalid weights revert to one, and invalid progress reverts to zero. Unknown keys carry no scheduling meaning. Normalized records, including sanitized metadata, form the boundary to projection and transport.

## Projection

[schedule.py](live_gantt/schedule.py) owns the pure `project(tasks, now)` function. It copies normalized inputs and returns enriched tasks, milestone summaries and projection warnings. Historical actual times never depend on estimates. Missing history stays missing. A completed task without an end is available now for dependency purposes and has no invented actual bar.

Each lane reserves all already-running work before scheduling pending tasks in identifier order. Completed tasks do not interrupt the remaining lane chain. Multiple simultaneously running tasks preserve observed reality and produce warnings; pending work waits for all of them. Explicit `blockedBy` edges add cross-lane prerequisites. A dependency graph schedules each pending start at the latest of now, its lane predecessor's finish and all blocker finishes. Missing blockers and cycles suppress dependent forecasts. An unestimated task stops its downstream lane projection rather than assuming zero duration.

An elapsed-hours Program Evaluation and Review Technique (PERT) estimate supplies mean `(low + 4 * likely + high) / 6` and standard deviation `(high - low) / 6`. Running work has remaining fraction `1 - max(progress, liveProgress) / 100`, measured from now. Zero progress beyond the expected elapsed duration marks overrun. Pending work uses its whole estimate. Dates outside the supported calendar produce warnings and unknown projections.

Milestone completion uses explicit task progress and relative weights: completed counts fully, in-progress counts proportionally, pending counts zero. The 50th-percentile (P50) date is the latest expected finish. For the 90th-percentile (P90) forecast, variance accumulates once per remaining task on the controlling prerequisite chain, scaled by the square of the remaining fraction. A prerequisite with the latest mean controls a join, with larger variance breaking ties; shared prerequisites are not counted twice. The latest chain end plus `1.2816` standard deviations supplies P90. This assumes independent task durations and approximates joins by their controlling chain. Unknown required durations keep the milestone forecast unknown.

## Local transport and idle behavior

[server.py](live_gantt/server.py) binds `ThreadingHTTPServer` exclusively to `127.0.0.1`. Request parsing checks that exactly one Host header equals `127.0.0.1:<bound-port>` or `localhost:<bound-port>` before dispatching any method. Fixed static routes prevent filesystem traversal. Responses have no cross-origin resource sharing headers and include a same-origin content security policy. JavaScript Object Notation (JSON) values are serialized without non-finite numbers. The browser renders source text through text nodes.

The server exposes fixed assets, the session index, a selected-session snapshot and Server-Sent Events (SSE). `Monitor` owns source access, cached source hashes and reader counts. It starts no polling worker until a stream is watched, then checks sources every two seconds. The final reader disconnect wakes and terminates the worker. Explicit requests can read sources without creating a background poller. Stream handlers detect closed sockets while waiting, and bound writes avoid retaining stalled clients indefinitely. Heartbeats run only for connected streams.

Each selected session's normalized source model is hashed independently of wall-clock projections. Only changed source models produce full `state` events. Index changes produce `lists` events. A comment and a timestamped `heartbeat` event are sent every 15 seconds, allowing the page to distinguish source inactivity from a disconnected connection. A normal state request recalculates projected dates even if its source hash is unchanged. The scheduler exports the overrun deadline and whether each milestone has remaining work so the browser can advance time without reimplementing scheduling rules.

## Browser and process lifecycle

[app.js](live_gantt/static/app.js), [style.css](live_gantt/static/style.css) and [index.html](live_gantt/static/index.html) make one buildless, offline page. The browser owns zoom, scrolling, visible-agent filtering and local advancement from the model's projection timestamp. It maintains its own now line without asking the server for clock-only updates. Scrolling pauses following; the user can resume it. Focus and hover expose task detail. Patterns and outlines distinguish statuses, system fonts use tabular numerals, and reduced motion disables pulses.

[__main__.py](live_gantt/__main__.py) selects the configuration root and fixed-loopback port and shuts down on interruption or termination. It starts no source work by itself. [The launchd template](launchd/local.live-gantt.plist) supplies the standard process type, niceness 10, low-priority input/output and bytecode suppression. Not the background process type: that band gets no CPU while the machine is busy, which is exactly when the chart is watched; idleness comes from doing no work without a reader instead. The template is the one definition of the agent's label and Python; [the installer](launchd/install.sh) reads both from it, adds the checkout, the user log and an explicitly set source root, then bootstraps the user agent, and prints the address from the server's own constants. [The uninstaller](launchd/uninstall.sh) stops that agent and removes its property list while retaining the log. Neither the server nor browser persists application state; transcripts reconstruct history after downtime.
