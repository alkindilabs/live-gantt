# Architecture

## Sources and ownership

[sources.py](live_gantt/sources.py) owns discovery, validation and transcript reconstruction. `SourceStore` holds incremental read state under serialized access. It reads the configuration root selected by `CLAUDE_CONFIG_DIR`, falling back to Claude Code's standard per-user directory. Task files are the authoritative current plan; parent transcripts supply creation, first start, last completion and progress history. Deleting a task file removes it from the plan even when transcript history remains.

Discovery combines task directories and parent transcripts, ordered by latest source modification. Source-owned recency and read budgets bound identity reads: recent or chartable sessions use a cached prefix and changing tail; old, non-chartable sessions expose identifier/date without reading identity files. Selection reconstructs full history. Title precedence is adjacent `custom-title.json`, latest transcript title, then first meaningful user prompt, excluding harness metadata and command markup. The latest working directory wins; a custom title retains the prompt separately.

Chartable means task or agent files exist; agent counts include ordinary and workflow transcript or metadata files. Headless comes from the initial `sdk-cli` entrypoint. Index activity shares the freshness rule. Lazy identity resolution bounds discovery cost without compromising selected-session history.

Parent and subagent transcripts are read by byte offset. Complete records are consumed, including a valid final record without a newline; incomplete trailing records wait for an append. Shrinkage, replacement or same-length rewriting resets the cache. Relevant substrings are checked before decoding, timestamps still track activity, and malformed records are skipped. Normal polling therefore processes appended data, although the first selected-session read scans its history.

Agent metadata supplies description and role; transcripts supply first/last activity and the latest tool-call description, cleared when absent. Parent terminal notifications resolve tool-result aliases and are recognized in user, queue and queued-attachment records. An agent's own `toolEndsTurn` result also completes it. Later activity resumes an agent and invalidates prior terminal signals. Inactivity without completion means silent, not finished; completed bars retain first-to-last recorded activity.

Workflow journals establish agent labels, phases and order; result lines and hand-back finish agents. Parent launch results name and date runs, with directory names as fallback; terminal notifications end them. Live runs are running if any agent runs, otherwise silent. Unfinished agents inherit terminal run state, or become stopped after successful completion. The incremental journal reader also supplies live progress, keeping completion counts consistent. Task metadata assigns ordinary or workflow agents; the browser filters unassigned agents to its window.

External runs stay live until explicitly ended. Log modification records activity. An unended run may supply a positive process identifier; signal zero tests existence without delivering a signal, and errors other than absence count as alive. Journal and log paths resolve relative to the task directory unless absolute or home-relative. These source paths remain read-only.

Metadata validates independently with task warnings: invalid estimates stay unknown, weights default to one, progress to zero, and unknown keys carry no scheduling meaning. Normalized records, parse success and modification times are the projection/freshness/transport boundary. `plan(list_id)` skips transcript scans for cheap hooks. The invented [compatibility fixture](tests/fixtures/claude-code-2.1.292) and [boundary test](tests/test_compatibility.py) pin observed private, unversioned formats without storing personal data.

## Projection

[schedule.py](live_gantt/schedule.py) owns pure `project(tasks, now)`, copying normalized inputs into enriched tasks, milestones and warnings. Recorded actual times never depend on estimates; missing history stays missing. A completed task without an end is available now for dependency scheduling but receives no invented actual bar.

Each lane reserves all running work before pending tasks in natural identifier order. Completed work does not interrupt the remaining chain. Multiple running tasks remain visible and warn; pending work waits for all of them. Explicit `blockedBy` edges add cross-lane prerequisites. A pending start is the latest of now, its lane predecessor's finish and all blocker finishes. A known forecast is queued when direct unfinished prerequisites finish after now, with identifiers in `waitingFor`. Missing blockers and cycles suppress dependent forecasts and mark affected successors blocked. Unknown estimates also stop downstream projection, but remain distinct from blocked or queued work; they never imply zero duration.

Elapsed-hour Program Evaluation and Review Technique (PERT) estimates supply mean `(low + 4 * likely + high) / 6` and standard deviation `(high - low) / 6`. Running duration uses remaining fraction `1 - max(progress, liveProgress) / 100` from now; pending work uses its whole estimate. Zero progress beyond expected elapsed duration marks overrun. Unsupported calendar results warn and remain unknown.

Each milestone independently weights reported task progress: completed counts fully, in-progress proportionally, pending zero. `hasRemaining` follows task status; even reported progress of 100 does not complete an unfinished task. `hasEstimate` means at least one remaining task is estimated, not that a complete forecast exists. The 50th-percentile (P50) value is the latest expected finish. The 90th-percentile (P90) approximation adds remaining variance once per task on the controlling prerequisite chain, scaled by remaining fraction squared. The latest mean predecessor controls a join, with greater variance breaking ties; shared prerequisites are not counted twice. The latest chain end plus `1.2816` standard deviations supplies P90. This assumes independent durations and approximates joins. Unknown required durations suppress milestone forecasts; calendar overflow can leave P50 known and P90 unknown. Completed milestones retain their latest recorded end when available.

## Freshness

[freshness.py](live_gantt/freshness.py) owns pure `assess(tasks, transcript_updated, now)` and the single definition of stale plans. It returns findings with rule, task identifier and plain-sentence message, session activity, and time since the newest task-file change. Discovery shares `session_active`; the browser and hooks do not recreate these decisions. The module owns all freshness thresholds and the scheduling fields imported by [the TaskCreate hook](hooks/task_created.py).

Findings cover unfinished tasks without a valid estimate or lane, in-progress tasks without numeric progress, old in-progress task updates during an active session, missing or quiet run logs during activity, and exited declared processes without later log activity. A log still being written outweighs an exited or reused process identifier; a process-exit finding replaces the same run's quiet-log finding. Run findings include an observed phrase for comparison with declared state. Completed, deleted and unreadable tasks produce no findings, preventing half-written task files from falsely making the plan stale.

## Local transport and idle behavior

[server.py](live_gantt/server.py) binds exclusively to `127.0.0.1`. Before dispatching any method it requires exactly one Host header matching `127.0.0.1:<bound-port>` or `localhost:<bound-port>`. Fixed routes prevent filesystem traversal. Responses omit cross-origin resource sharing headers and include a same-origin content security policy. JavaScript Object Notation (JSON) serialization rejects non-finite numbers, and the browser inserts source text through text nodes.

The transport supplies fixed assets, session discovery, a selected-session snapshot and Server-Sent Events (SSE). The favicon's inline Scalable Vector Graphics (SVG) mark takes its status colors from the stylesheet. `Monitor` owns source access, cached hashes and reader counts. It starts polling only while a stream is watched; the final reader wakes and ends the worker. Explicit requests read without starting background polling. Handlers detect closed sockets while waiting and bound socket writes so stalled clients cannot retain them indefinitely. Heartbeats exist only for connected streams.

Hashes include normalized source and freshness verdict, excluding projections and seconds-since-change. Time alone can therefore emit a newly stale `state` without broadcasting unchanged models each tick. Discovery changes emit `lists`; timestamped heartbeats distinguish inactivity from lost connections. Explicit requests always recalculate projection. The server owns polling/heartbeat intervals; exported overrun time and remaining-work status let the browser advance time without duplicating scheduling.

## Browser and process lifecycle

[app.js](live_gantt/static/app.js), [style.css](live_gantt/static/style.css) and [index.html](live_gantt/static/index.html) form one buildless, offline page. The selected session provides the work context; its progress overview precedes the detailed timeline. Each unfinished milestone has a prominent server-derived percentage, progress bar, expected finish and later estimate. Milestones remain independently weighted: the browser invents neither an aggregate percentage nor an aggregate probability. Dates are estimates, not deadlines. Missing P50 is distinct from missing P90; no remaining estimates prompts estimation, while an incomplete forecast remains unavailable. Completed planned tasks are named as such, without implying that agent activity or all development has ended. Agent-only sessions show activity without fabricating a task percentage or finish date. Stale or disconnected state is visible beside the forecasts.

A listbox popover supports filtering and multi-line session identity. It includes chartable and selected sessions; All sessions adds the rest. Every filter word must match identity, project or identifier, and a browser-owned cap bounds rendered results. Keyboard navigation, Enter, Escape and `/` provide selection, dismissal and opening. `#session=<id>` persists through replacement history, reloads and hash changes; absent a link, the first chartable session is selected. Selected identity survives discovery updates.

The browser owns zoom, scrolling, visible-agent filtering and time advancement from the server's projection timestamp. Fit includes task history and forecasts, task children, detached agents and workflow runs, so historical agent-only work remains reachable. The default zoom and past/future share are browser constants. Horizontal scrolling pauses following; Follow now resumes it. Connection announcements change only when connection state changes, while a separate visual counter shows receipt age without repeated announcements. No clock-only request is needed to move the now line or projected dates.

Readable task subtitles expose state, progress, update age and observed run findings. Queued state, prerequisites and freshness messages come directly from the server. Selecting work opens docked details, moves focus to Close and restores focus to its trigger on close; Escape also closes it. Details follow the selected record across updates and close when it disappears. Raw metadata is collapsed behind a disclosure. The status key is another disclosure, keeping explanatory material available without dominating the work view. Status patterns and outlines supplement color, tabular numerals aid comparison, and reduced motion disables pulses.

Agent/run bars show descriptive activity or state. Labels fit inside the right edge or follow the bar without clipping. Old completed tasks fold by lane and milestone with count and recorded hours; finished/failed attempts fold into expandable marks, while running/silent agents retain rows. Workflows have their own lane, badge and expandable finished children. The browser owns completion recency. Only zoom and session-scoped expansion persist in guarded local storage; storage failure never prevents rendering.

[__main__.py](live_gantt/__main__.py) chooses the configuration root and loopback port, starts no source work by itself, and shuts down on interruption or termination. Transcripts reconstruct session history after downtime.

## Plugin and task planning

[The manifest](.claude-plugin/plugin.json) owns release version and identity; [the marketplace](.claude-plugin/marketplace.json) names the repository root as its sole plugin. [The live-gantt skill](skills/live-gantt/SKILL.md) is the task-metadata contract, including dependencies. Hook registration resolves scripts from the plugin root, independent of session working directory. The TaskCreate hook examines the successful tool response and supplied metadata to add advisory context for missing scheduling fields. It never writes tasks or blocks tools, and malformed input is silent.

[The freshness hook](hooks/freshness.py) assesses task files and event transcript modification time without scanning history. Stop may block with findings, guarded against recursion and repetition. UserPromptSubmit adds findings as context; PostToolUse is throttled, reading only cooldown state while throttled. One per-session JSON file under `CLAUDE_PLUGIN_DATA`, or the installed-files directory, stores cooldowns. Unwritable state is silent to avoid repeated messages. Unreadable tasks, malformed events and errors exit successfully; tasks and transcripts are never written.

[The open command](commands/open.md) checks the local server. When unavailable it explains persistent installation and asks before invoking it, allowing task-planning guidance without an installed service.

## Installation and service lifecycle

[installation.py](live_gantt/installation.py) owns platform choice, stable user paths, service rendering, replacement and removal. Entry points delegate after checking the running Python version; no package installation occurs. The service runs a copy independent of plugin caches. macOS uses user Application Support; Linux honors absolute `XDG_DATA_HOME`/`XDG_CONFIG_HOME`, otherwise standard user directories.

An update stages replacement files before stopping the service, then replaces the package as a whole so removed files cannot survive. The version marker changes only after service registration succeeds. Failure reports an error and leaves the previous marker for a later retry; installation is not a rollback transaction. An explicit `CLAUDE_CONFIG_DIR` override is saved beside the installed package and reused on upgrades unless supplied again; an explicitly empty value clears it. Installation never changes Claude Code's files.

The [launchd template](launchd/local.live-gantt.plist) owns its label and low-priority standard-process policy: background process type would starve the chart, so idleness comes from having no readers. The [systemd unit](systemd/live-gantt.service) likewise uses low-priority, non-idle scheduling, login startup and user-journal logs. Rendering supplies interpreter, working directory and logs, quotes paths, escapes systemd specifiers and disables environment expansion to preserve literal dollar signs.

[SessionStart](hooks/session_start.py) shares installer paths and markers. Only an older installed stable version refreshes/restarts the opted-in service; absent, malformed, equal or newer markers do nothing. Errors are advisory and silent, while the open command exposes them. Uninstall stops/unregisters the service and removes package, override and marker, retaining logs. Marker removal preserves the opt-out across sessions; unchanged versions do no service work.
